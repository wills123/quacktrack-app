# Quack Track

An internal operations tool (Dockerized Nginx + PHP + MySQL) that started as a
simple product-ordering/van-stock tracker and has since grown into the
day-to-day system for inventory, ordering, field-asset tracking, and a few
third-party integrations. This README reflects the app's current feature
set, not just its original scope.

> **Note on this repository:** this is an export of the application code and
> runtime configuration only (no internal docs, ops notes, or test suite).
> It's meant to give someone reviewing the code a clear, accurate picture of
> what's here and how to run it locally.

## What it does

- **Products & inventory** — product catalog with image uploads (JPG/PNG/GIF,
  stored under the MIME type actually detected, not the uploaded filename),
  categories, manufacturers.
- **Ordering** — cart with quantities/notes, bulk-add by SKU, saved order
  templates, favorites, per-store ordering, order history with reorder,
  checkout-time stock/status validation (`CHECKOUT_VALIDATION_ENABLED`,
  `MAX_ORDER_QUANTITY`), and emailing orders out (pre-filled Outlook draft).
- **Van stock & receiving** — add/use/adjust van stock per store, a
  transaction history, and a receiving flow for incoming stock.
- **Regions & stores** — multi-region/multi-store structure; each region
  controls its own self-registration (`allow_registration`).
- **Deployments, forms & surveys** — a deployment tracking module
  ("Deployment Quest Log", tied into the QuickQueue integration below), a
  form builder, and a survey module with response tracking.
- **Asset tracking** — asset review/templates and kit templates, with
  optional integration into Snipe-IT (see below) for tracked assets.
- **Travel** — a travel-tracking module.
- **Reporting** — in-app reports plus a Power BI export endpoint.
- **Admin dashboard** (`/admin`) — regions, stores, users, categories,
  manufacturers, stock settings, email templates, API keys, migrations,
  and admin-facing logs/session views.

## Integrations

These are optional and off by default; each is gated by its own `*_ENABLED`
flag in `.env`:

- **Snipe-IT** (`SNIPE_IT_ENABLED`) — asset browsing, checkout, and
  reporting against a Snipe-IT instance, with an optional OAuth-based SSO
  flow (`SNIPE_IT_OAUTH_ENABLED`).
- **Acumatica ERP** (`ACUMATICA_ENABLED`) — live stock levels, shipment
  tracking, and purchase-order creation. POs this app creates always land
  in Acumatica **on hold**; Quack Track never releases one itself.
- **QuickQueue** (`QUICKQUEUE_API_BASE_URL`) — read-only ConnectWise project
  lookups via QuickQueue's API (QuickQueue owns the ConnectWise connection;
  this app never talks to ConnectWise directly).
- **Cloudflare Turnstile** (`TURNSTILE_ENABLED`) — bot protection on
  registration/login/password-reset.
- **Power BI** — a reporting export endpoint for external dashboards.
- **External orders API** (`/api/external/orders.php`) — a separate
  API-key-authenticated endpoint (see `app/includes/api_key_auth.php`) for
  programmatic order submission, independent of normal session auth.

## Architecture

- **nginx** (reverse proxy + static file serving for `/assets` and
  `/uploads`) → **PHP-FPM** (application) → **MySQL 8**, each its own
  container via Docker Compose.
- The database connection uses TLS by default, verified against a private
  CA that's generated by a one-shot `quacktrack-db-certs` container on
  first start (`docker/mysql/init-certs.sh`); plaintext DB connections are
  only accepted with `APP_ENV=dev` or `DB_ALLOW_PLAINTEXT=1`.
- `docker-compose.yml` is the straightforward single-stack setup (below).
  `docker-compose.release.yml` + `docker-compose.router.yml` describe a
  separate blue/green release layout (two app stacks behind a router,
  swapped by a deploy process) — not needed to run this locally.
- All routing goes through `app/router.php`; direct access to other `.php`
  files is not allowed by nginx (see `nginx/default.conf`).

## Prerequisites

- Docker Desktop, or Podman with `podman-compose` (Podman works on Fedora/Nobara)

## Setup

1. Create the project env file:
   - Copy `.env.example` to `.env` and set strong values for at least:
     `APP_SECRET` (32+ random hex chars), `ADMIN_EMAIL`, `ADMIN_PASSWORD`,
     `MYSQL_ROOT_PASSWORD`, `MYSQL_PASSWORD`.
   - `APP_URL` must be the real public origin used for password-reset
     links. For local HTTP development, use `APP_ENV=dev` and
     `APP_URL=http://localhost:8081`.
   - For production behind HTTPS termination, set `SESSION_COOKIE_SECURE=1`.
   - Leave every `*_ENABLED` integration flag at `0` unless you're actually
     configuring that integration.
2. Start the stack:
   - `docker compose up -d` (or `podman compose up -d`)
   - First start also builds the DB's TLS certificates via the
     `quacktrack-db-certs` one-shot container — this runs automatically
     before MySQL starts.
3. Run migrations (needed after a fresh database, or anytime a page
   reports missing columns):
   - `docker compose exec quacktrack-php php /var/www/html/app/run_migrations.php`
4. Sign in:
   - Visit `http://localhost:8081/login.php` with the admin credentials
     from `.env` (the admin account is created automatically on first run
     from `ADMIN_EMAIL`/`ADMIN_PASSWORD`).

- **Orders**: `/orders` — history and reorder

## Security notes

- CSRF tokens required on all state-changing requests; rejected with a 400
  if missing or invalid.
- All database access goes through prepared statements.
- Passwords hashed via PHP's `password_hash` (bcrypt/Argon2 depending on
  PHP build).
- Role model: `users.role` holds a legacy value (`admin`/`manager`/`user`)
  that's synced into a proper roles/permissions system
  (`sync_user_role_assignment()`); permission checks (`require_permission()`)
  gate individual pages and actions rather than relying on the role string
  directly.
- Session hardening: sessions validate the User-Agent, expire after
  `SESSION_TIMEOUT` seconds of inactivity (default 3600), and rotate their
  session ID on login/registration and every 30 minutes of authenticated
  activity (a short-lived alias covers in-flight requests across a
  rotation; it carries no authenticated state and can't be used to resume
  a logged-out session).
- Account lockout after repeated failed login attempts.
- Uploads: nginx refuses to execute PHP from `/uploads`; uploaded images are
  re-encoded/stored under the extension matching their *detected* MIME
  type, not the filename's extension, so a mismatched upload is served as
  inert bytes rather than executed.
- Security headers (`X-Frame-Options`, `X-Content-Type-Options: nosniff`,
  `Referrer-Policy`, CSP, HSTS) are set both by the app and by nginx for
  static/error paths that never reach PHP.
- Login and the deploy webhook are rate-limited at the nginx layer
  (`limit_req`).
- Security-relevant events (logins, registrations, lockouts, etc.) are
  logged via a dedicated security-event logger, separate from general
  error logging.
- Use HTTPS in production, with `SESSION_COOKIE_SECURE=1` set behind TLS
  termination.

## Backups

- MySQL data persists in the named Docker volume `quacktrack_db_data`.
- To back up: `docker compose exec quacktrack-db sh -c "mysqldump -u$MYSQL_USER -p$MYSQL_PASSWORD $MYSQL_DATABASE" > backup.sql`

## Stop and remove

- `docker compose down`
- To remove data (CAUTION, irreversible): `docker volume rm quacktrack_db_data`
